# 项目介绍话术

## 1. 一句话版本

这是一个基于 CrewAI 构建的多 Agent 自动化投研系统，能够围绕指定公司自动完成市场信息搜集、SEC 财报与监管文件检索、财务指标分析，以及投资备忘录初稿生成。

## 2. 给 HR 的介绍版本

我做了一个面向投研场景的 AI 多 Agent 系统，目标是把分析师最耗时的资料搜集和初稿整理流程自动化。

用户输入公司名称后，系统会把任务拆分给多个角色：

- 信息搜集 Agent 负责搜索公司近期动态、竞争格局和风险点
- 财报分析 Agent 负责调 SEC 数据、提取财务事实并计算关键指标
- 报告撰写 Agent 负责把前面两部分整合成结构化投资备忘录

这个项目的重点不只是“让大模型写报告”，而是把工作流拆成多个角色、多个步骤，并且接入外部数据源、异常处理和测试体系，让结果更可控、更可追溯。

从能力上看，这个项目体现了：

- 多 Agent 系统设计能力
- 外部 API 集成能力
- 数据检索与结构化分析能力
- 工程化稳定性和测试能力

## 3. 给技术面试官的介绍版本

这个项目本质上是一个基于 CrewAI 的顺序式多 Agent 工作流。

我把投研流程拆成了三类 Agent：

- `information_gathering_analyst`
- `financial_statement_analyst`
- `report_writing_analyst`

并通过 4 个 Task 串成一条从输入公司到输出报告的链路：

- 市场情报
- filing 复核
- 财务分析
- 最终投资备忘录

在实现上，我重点做了几件事：

- 用 YAML 管理 Agent 和 Task，降低 prompt 配置和 Python 逻辑的耦合
- 接入 Google Search、SEC filing、SEC company facts、财务指标计算等工具
- 对 401/403/429 这类外部错误做统一终止和用户提示
- 限制危险工具暴露范围，避免模型乱读文件、乱写文件
- 为配置、结构、工具、CLI、财务逻辑补充自动化测试

所以这个项目的价值在于：它不是一个单轮问答 Demo，而是一套可运行、可验证、可扩展的 Agent 工作流原型。

## 4. 严谨版项目价值描述

当前可以严谨声称的是：

- 项目已经实现了端到端自动化投研工作流
- 具备多 Agent 协作、外部数据接入、财务分析和报告生成能力
- 具备错误处理、工具约束和自动化测试
- 适合作为投研自动化和企业研究自动化的原型系统

当前不应直接声称的是：

- 已经提升了多少百分比效率
- 已经节省了多少小时人工时间
- 已经显著提高了多少准确率

因为这些数字需要基于对照实验和样本数据验证。

## 6. 面试时如果被追问“价值是什么”

你可以这样回答：

这个项目的价值不在于替代分析师做最终判断，而在于自动化掉投研流程里最重复、最耗时的前置环节，比如资料搜集、财报定位、基础财务分析和初稿整理。这样分析师可以把更多时间放在高价值判断上。当前我已经完成了工程实现，下一步会通过对照实验去量化它在耗时、成功率和人工修改率上的收益。

## 7. 面试时如果被追问“难点是什么”

你可以这样回答：

最大的难点不是把模型接起来，而是让整个流程稳定、可控、可验证。比如：

- 多 Agent 的职责边界怎么拆
- 外部 API 失败时怎么处理
- 模型工具调用不稳定时怎么约束
- 中间结果如何沉淀，避免最后一步黑盒输出
- 如何通过测试去证明关键能力没有回归

我在这个项目里重点解决的就是这些工程化问题。
